# 实现完整性

代码、测试、调试前读取；无产品代码时不能伪造运行结果。

- 必需数据缺失/无效显式失败，不能返回任意 0、空集合、null、false、空串或 Unknown 冒充成功。区分 absent、valid empty、failure；只有产品语义明确允许的 fallback 才合法，使用位置注明依据。unknown/pending 只表达真实状态。
- 业务失败自然传播；API/controller/worker 边界补上下文并重抛或返回显式错误，不吞成成功形状。重试有理由、次数边界、部分提交和幂等/对账处理；结果未知的外部副作用先核对，见 ADR-008。
- 实现一般规则，不硬编码样本答案。测试具体值、状态转换、边界、副作用和失败；仅 truthy、存在性、no-throw 不证明业务正确。删除核心逻辑测试仍通过时，补足真正验收证据。
- 可测 bug：最小复现 → 观察同一测试真实 RED → 根因修复 → GREEN → 受影响回归。不可复现/无环境时提供可重复路径和限制，不倒写 RED。测试存在、命令退出 0、窄 suite PASS 是不同事实。
- 运行前核实命令及副作用；检查真实环境身份、测试数据和授权，不假定 GET 或名为 sandbox 的 DB 安全。记录失败、skips、NOT_RUN、BLOCKED，不把环境阻塞写 PASS。
- 疑难诊断 probes 保留到端到端核验；交接写残留路径和移除条件，不含凭证/个人数据。不得为了测试直接修改真实业务 DB 来替代应用流程。

本项目重点不变量：项目引用与文件/缓存/thread 隔离；品牌确认由用户命令；BYOA 不静默转 BYOK；任务成功以已校验文件及持久记录为准；外部调用不承诺 exactly-once。原文及测试场景由 [文档入口](../../README.md) 定位，这里不复制产品状态机。
