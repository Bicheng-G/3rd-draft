# 架构决策记录

记录日期：2026-10-02。`accepted baseline` 表示本次产品/架构工作采用的设计基线，**不表示已实现或经过用户逐条审批**。涉及运行时可用性的条目仍受 M0 限制。

本轮范围注记：用户明确将 v0.1 定义为 Walking Skeleton、V1 定义为完整产品。ADR-001～012 原文保留；其中完整图片能力与发布阶段的历史“v0.1/M0”约束现归 V1。本次以 [ADR-013](#adr-013--walking-skeleton-以跨次文本创作证明项目记忆闭环)限定实施范围，运行通过以[验证证据](../product/validation-v0.1.md)为准，不从 accepted 状态推断。

## ADR-001 — 本地浏览器工作台 + 常驻本地服务

**状态：accepted baseline，用户确认使用形态。** 单人在 Windows 使用多个项目；服务连接本地 runtime、保存任务和文件，浏览器展示工作台。

理由：匹配已有订阅与本机执行；浏览器关闭后状态和任务仍可保留。代价是安装、机器休眠和本地数据备份需要处理。

未采用云 SaaS、Vercel 作为首要宿主或先做 Electron。若用户明确需要远程/多人，再评估认证、配对与同步，不能直接暴露本地服务。

## ADR-002 — 先验证 Codex 原生路线，保留 BYOK 与人工桥接

**状态：conditional，等待 M0。** 将原生登录/runtime 作为首个候选；SIWC 是不同路线，暂不并行实现。

理由：更贴近 BYOA 偏好，官方资料支持值得测试的能力方向。代价是实验性协议、版本差异和能力不完全可见。

若生图/编辑/回收/隔离不通过，不宣称自动闭环完成；明确缩小技术预览，或由用户选择 API 生产路线。禁止静默改账单。

## ADR-003 — 应用拥有领域知识，runtime 拥有任务内部执行

**状态：accepted baseline。** 品牌、来源、brief、版本和资产保存在本地应用；runtime conversation 是可替换执行上下文。

理由：跨项目隔离和跨 provider 可移植性是基础需求。代价是需要 ContextManifest、导入和结构化交接。

不采用 provider 聊天历史作为唯一记忆，也不依赖登录后自动获得 ChatGPT Project sources。

## ADR-004 — SQLite + 文件资产，先结构化/全文检索

**状态：accepted baseline，驱动/版本待安装验证。** 单个本地服务写 SQLite，图像存文件，通过哈希和 manifest 关联。

理由：本地单人规模无需部署数据库服务。代价是数据库/文件一致性、备份和 schema 迁移需显式设计。

暂不引入 Postgres、Redis、向量数据库；若出现实际性能/团队并发要求，再以基准和数据迁移方案重议。

## ADR-005 — 固定主工作流 + 有界多角色任务

**状态：partially superseded by ADR-011（2026-10-02）。** “固定主工作流”由按需项目任务替代；以下执行控制与角色职责继续有效：应用状态机拥有任务、预算和审批；Research/Strategy/Production/Review 承担判断责任。原生 runtime 内部循环不再被另一个自主总控重复管理。

理由：同时满足协作与可恢复性，不让 agent 群聊成为状态来源。代价是初期流程自由度有限。

参考 LangGraph 的 checkpoint 思路但暂不引入框架。动态并行/恢复复杂度超过小型状态机时再评估。

## ADR-006 — Skill、Style Profile、Brand Pack 分离并锁版本

**状态：accepted baseline。** 开放 Skill 入口格式 + 平台能力/权限 sidecar；全局安装、项目启用、单次锁定分开。

理由：创作方法需要复用，品牌事实不能随 Skill 混入其他项目。代价是兼容性和内容哈希管理。

不做首版 Skill marketplace，不将外部脚本默认视为可信，也不为格式兼容承诺输出一致。

## ADR-007 — 同时允许整体生成与确定性合成

**状态：accepted baseline。** 创意整图适合需要画面与文字一起构思的内容；精确品牌文字使用基础分层模板。

理由：既保持视觉表达自由，也提供可控文字/标识路径。代价是维护两类制作血缘与不同检查方式。

首版只做基础模板，不扩展为任意画布。模板能力不足引发频繁人工外部编辑时，再评估更深编辑器。

## ADR-008 — 不确定副作用先对账，禁止盲目重试

**状态：accepted baseline。** 入库用唯一标识与事务；外部图片调用若不知是否完成，进入 result_unknown。

理由：模型调用可能已经消耗额度且产物尚未回收。代价是少量情况下需要用户处理，而非始终自动恢复。

只有 provider 支持可验证幂等/查询时才能增强自动重试，不能仅凭内部 request hash 宣称防重复扣费。

## ADR-009 — 以真实任务评测选择模型与编排

**状态：accepted baseline。** 第一版不按厂商宣传建立复杂自动 router；对照手工基线衡量质量、操作时间、修改成功率和调用预算。

理由：用户已有较高质量预期，但本次没有历史图片可比较。代价是上线前要准备真实评测材料。

不把 adoption 当点击/转化效果，不把固定 seed 当可重现像素，不把多 agent 数量当产品价值。

## ADR-010 — 成品导出与私有备份分开

**状态：accepted baseline。** 日常成品包只包含需要交付的图文和精简 manifest；完整项目备份另行包含知识和内部血缘。

理由：避免用户交付图片时带出内部研究/提示词，同时保证可迁移。代价是两种 manifest 的校验和恢复流程。

若未来需要公开复用整套创作 recipe，再增加显式选择的分享模式；不改变默认成品包内容。

## ADR-011 — Living Project + 独立、可恢复的项目任务

**状态：accepted baseline，依据用户 U-13～U-16；替代 ADR-005 的固定主链路。** Project Memory 是长期中心；research、synthesize_insights、ideate、develop、produce/revise、deliver 各有明确入口和产物。研究与洞察建项时可选，之后手动触发；创意默认使用已有资料。

理由：用户常常只 brainstorm、收藏或制作一两个 post。长期知识不应依附某次制作，已收藏想法也不应被迫重新走研究和概念板。代价是需要独立任务状态、跨次来源引用和过期提示。

保留 Workflow Service 的持久状态、批准、能力检查、预算、重试与恢复；自由选择入口不等于任意 agent 画布。单 Main Agent 是待评测执行策略，不当作用户已撤回 U-08；逻辑职责可由同一 runtime 承担，任何角色都不能直接更改领域真相。

验证：T-29～T-36；实现与效果未实测。若多入口导致用户不理解下一步，优先改入口与可见状态，不回退到每次自动研究。

## ADR-012 — 项目创意独立持久化，收藏固定版本，记忆按相关性检索

**状态：accepted baseline，依据 U-15/16 的架构取舍。** CreativeIdea 属于 Project，内容继续使用 ConceptVersion；CreativeSetConcept 关联一次工作与具体版本。Favorite 是版本书签，可与多次使用并存。Insight 拥有不可变版本及证据引用。具体字段是本次设计，不声称用户逐条指定。

理由：所有创意都值得可追溯保存，收藏只标记再取用意愿；set 归档不能让好点子消失。代价是增加关联、版本及完整备份覆盖。没有已实现数据库，本次是契约修订，不伪称完成数据迁移。

下一轮通过 Context Builder 选取相关品牌约束、洞察、历史创意与反馈并记录理由；不全量塞入历史，不从收藏自动产生品牌规则或效果结论。品牌变更仍须用户确认。v0.1 仅支持创意收藏，通用收藏、自动 taste 建模、广告表现接入及定时研究留待后续。

沿用 ADR-004 的 SQLite + 文件与结构化/全文检索，不引入图数据库、向量数据库或训练系统。验证：AC-19/20、T-30～T-36；长期质量提升未实测。

## ADR-013 — Walking Skeleton 以跨次文本创作证明项目记忆闭环

**状态：accepted implementation scope；依据本轮用户明确的阶段划分。** v0.1 只证明项目知识或有范围的创作反馈在持久化与服务重启后，能经相关上下文影响下一次真实创作。文字 caption/创意文案是足够的本次作品；原完整产品需求保留为 V1，不能把本次通过解释为图片生产、视觉质量或完整 AC 通过。

沿用 ADR-001/003/004/008/011/012 的本地浏览器 + 常驻服务、应用拥有记忆、SQLite + 文件、结果未知先停止重发和相关性检索。root 负责整合与 acceptance，应用服务是领域写入与任务状态的唯一 owner；runtime 不直接访问业务数据库或自行扩大任务。

本次最小实现采用 **Node.js 22.15.0 的内置 `node:sqlite`**，本机 probe 报告 SQLite 3.49.1；该 Node 接口仍是 experimental，记录实际运行环境和限制，不宣称已验证其他版本/安装组合。前端采用浏览器原生 ES modules 与静态资源，暂不引入候选 React/TypeScript 构建依赖。当前界面与任务规模不需要额外框架；后续出现具体维护或交互需求时可重新评估，并非永久技术限制。

执行只接入一个 **tool-free Codex 原生 ChatGPT 认证文本 runtime**：服务发送已选上下文和锁定内容哈希的随应用创作能力，取得结构化文字结果，经验证与归档后标成功。该路线不继承项目外工具、MCP/插件、跨项目会话或自由文件访问；只设置工作目录不足以证明隔离。原生登录状态已由 root 检查为 ChatGPT，但登录本身不等于任务执行、隔离或结果回收通过；这些另行实测。没有静默 BYOK，也不因本次 adapter 支持文本就声称支持图片、搜索或图片修改。

能力包的方法与品牌知识分离，版本/哈希进入不可变输入快照。一个受控随应用能力足够；第三方 Skill 导入、升级管理、复杂编排和 provider router 留待实际需求。通过具体版本引用连接作品、反馈和下一次 context，不新增第二套记忆真相或以 provider 聊天记录替代持久化。

错误边界：能力、认证、输入、项目引用或归档校验失败时不得返回成功；提交后中断且无法确认结果时保存 `result_unknown`，不自动重发。服务重启保留作品、上下文与历史，已知成功不重跑；模型输出不能自行确认品牌事实或提升反馈范围。工具被禁用及项目数据只由宿主按 scope 提供是本次隔离边界，须有配置与负例证据。

代价与限制：本次不能验证视觉生产、完整收藏/洞察/Creative Set 工作流、完整备份恢复或长期质量提升；内置 SQLite 的 experimental 状态和 CLI 版本变化均需保留实测限制。选择零前端依赖减少本次安装与构建面，但不会取消后续可用性与维护成本评估。

验证：[v0.1 关闭标准及记录](../product/validation-v0.1.md)。至少两次真实创作调用，中间重启服务；第二次 brief 不重复前次反馈，manifest 与真实结果共同证明复用；另验项目隔离、品牌确认、不可变哈希、归档、浏览器操作与故障状态。未附运行证据的部分仍为 NOT_RUN。此 ADR 只覆盖本次实现；通过后停止，不自动实施 V1。

## ADR-014 — V1 沿用本地领域模型，扩展版本化创作与受限视觉输入

**状态：implemented engineering decision，完整 V1 验收未通过。** 依据用户在 v0.1 通过后明确要求继续完整 V1 和英文产品 UI。ADR-013 保留为历史范围；不把新增页面或导入图片视为原生生图通过。

沿用 Node/SQLite 与原生浏览器模块。schema v2 解除每次 run 只能有一个 concept 的约束，允许手工创意无 run；保留旧 payload 和不可变归档。新增具名 evidence/insights/sets/briefs/assets/reviews/selections 及同项目外键关联，收藏理由和 archive 生命周期与内容版本分开。服务先取得数据根锁，再迁移；不新增第二套 IdeaVersion、provider 聊天记忆或通用工作流框架。

用户手动读取已知公共 URL（有界下载、每次重定向重新验证、DNS 地址固定并拒绝私有地址）或保存观察；洞察整理只读用户选定的已有证据。创意自动复用相关、未过期的来源和洞察，不自动访问网络。Skill 全局不可变导入、项目按版本启用，脚本只存不执行；权限/能力不兼容时阻止运行。

图片解码和一个确定性分层模板采用 sharp 0.35.5；ZIP 写入采用 fflate 0.8.3，备份读取另用有输出上限的 DEFLATE 校验。两者是已有图片/便携归档要求的直接实现依赖，不扩展为编辑器。导入 PNG/JPEG/WebP 完整解码后归档 PNG，去除元数据；模板精确渲染文字并保留视觉/logo/文案参数，溢出和缺字体报错。原生整图生成与指令编辑仍被能力门禁禁止。

tool-free Codex 文本路线增加显式选定 PNG 视觉输入：应用复制最多 8 张图到单次临时目录，无任意调用者路径，无宿主工具；应用视觉副本限制在 1024×1024，原文件保持，记录两种哈希与转换政策。用途是图像信息草稿提取、相关创意和独立 Reviewer。模型不能确认品牌、采用作品或消除旧阻断项。用户解释并解决 Review 阻断项，最终导出再校验当前 brief/品牌版本；caption 修改生成新资产版本，不生图。

原生图片探测发现工具存在，但没有验证硬调用上限和 reference 路径隔离。源码资料的 hook fail-open 行为与实装二进制边界证据分别记录，不能把公开源码当实装 revision。当前图片 adapter 在任何提交前返回 unsupported_capability，无自动 API/其他 runtime 降级；这使 AC-07/08 和完整 M0 保持 BLOCKED。

代价：保留单 agent 任务派发上限；结构化 JSON payload 与关系链接需一起校验；本地文件和数据库不跨介质原子提交，持久 runtime 输出只重试归档。备份限定单项目/64 MiB/512 条目/10,000 行，恢复只写新目录。SQLite experimental、特定 CLI、Windows 字体与视觉缩小限制继续明示。验证与未完成部分统一见 [V1 记录](../product/validation-v1.md)。

实测修正：1,000 图片在隐藏 library/Studio 同时全量创建 DOM，项目切换和列表 p95 超标。保留现有服务快照与筛选语义，只按活动视图渲染图像列表并采用 50 张/页；所有记录仍可按页访问，不引入新的缓存真相或虚拟滚动框架。用真实浏览器、总记录数及跨页身份核验复测，历史失败样本保留。
