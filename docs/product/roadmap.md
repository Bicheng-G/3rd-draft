# 实施路线图、风险与待定事项

状态：V1 已获实施授权，尚未验收 · 2026-10-02。实际差距与新增证据见 [V1 验证记录](validation-v1.md)；已完成文字阶段见 [v0.1 历史记录](validation-v0.1.md)。阶段定义不代表运行通过。

上一轮结束状态：六项 Walking Skeleton 关闭标准均 PASS，20 项工程测试通过，两个真实文本创作经进程重启证明反馈复用。随后用户明确要求完整 V1 和英文产品界面，因此本轮继续；先前的停止边界仍是历史事实，不再阻止新授权范围。

## 当前停止边界（2026-10-05）

保留已完成三项领域修正、独立 runtime profile 与有界兼容探针。产品负责人后继批准每个显式 Production Action 最多 2 次图片操作，可由 harness 强制执行；当前项目隔离/staged 文件区可读，正常宿主与其他项目禁止。旧的两次操作/工作子目录外读取不直接构成 blocker，按 ADR-016 重新验证控制、应用独立交互登录与真实订阅路线。通过则只完成 Generate→归档→一次指令 Edit→新版本并停止 dogfooding；否则以具体剩余边界失败停止。不扩展 API/BYOK、其他 provider 或外围 V1。完整事实、已运行检查、最低后续验收证据见 [V1 验证记录](validation-v1.md)。

本轮实际停止：两次操作 harness 机制与独立认证已证明；实装 Windows 项目文件系统正例不可用，个人原生 Skill 可显式进入上下文，门禁关闭。登录浏览器缓存又使 profile 检查超过上限。107 项回归通过验证拒绝行为，真实订阅推理与 Generate/Edit 仍 NOT_RUN。后续须选择能满足这些边界的 runtime/harness/executor，不能直接开始 dogfooding 原生图片。

| 3 | B-05/16 的手动研究与洞察，加 B-06 的独立构思/选择/发展 | 在项目/版本基础上实施；不因材料缺口自动研究 | 来源身份、洞察假设及版本引用；T-29～T-35 |

合成项目可先验证工程流程，但不能代替真实品牌质量评测、用户采用判断或可靠的手工操作时间。FR-17/18 与其他明确 P1 项保持延期。缺少外部输入时记录具体未完成项并继续独立工作，不将 V1 标为完成。

## 历史 v0.1 顺序与停止条件

本轮用户明确将首个里程碑缩为可用的跨次创作闭环。先固定[关闭标准](validation-v0.1.md#关闭标准)，再执行下列最小切片；root 保留范围、共享契约、集成和验收责任，worker 只在约定文件与接口内实施。

| 顺序 | 切片与责任 | 依赖 | 退出证据 |
|---|---|---|---|
| 1 | root 核对仓库、范围及共享契约；runtime worker 验证一个原生文本路线 | 文档基线与现有授权 | 实际环境、认证路线、工具隔离和失败边界有证据；未通过不得假设可用 |
| 2 | root 实施本地服务、SQLite 项目记忆、版本、反馈、ContextManifest 和归档 | 1 的领域与 runtime 接口 | 项目引用被校验，相关材料可解释选取，旧版不可覆盖，失败不生成成功记录 |
| 3 | runtime worker 实施 tool-free 文本 adapter；UI worker 实施中文浏览器闭环；文档 worker 同步范围 | 共享契约明确后并行；root 控制共享文件 | 一次用户动作可完成任务并读取作品、路线和上下文；各端对相同契约验证 |
| 4 | root 集成，执行边界测试与真实两次创作；worker 可独立审阅 | 2、3 | 重启后的第二次输出实际复用前次知识/反馈；记录全部运行和限制 |
| 5 | root 修必要缺陷、核对差异、记录验收并停止 | 关闭标准均有证据 | 本次通过或未通过如实记录；不自动开始 V1 |

一个随应用提供且锁内容哈希的文本创作能力足够，不要求建设 Skill 导入系统。原 M0 的图片与研究试验、M1～M3 的完整图文产品发布门槛保留为 V1 工作，不是本次的先决条件；原有 B/R/O/FR/AC/T 编号继续可追溯。

## V1 M0～M3 实施与验收基线（本轮适用）


```mermaid
flowchart LR
    M0[M0 原生能力与隔离验证] --> M1[M1 最小创作闭环]
    M1 --> M2[M2 日常生产与恢复]
    M2 --> M3[M3 对照评测与本地发布]

```

不承诺日期：完整产品尚无经过原 M0 的工程估算。以下保留原阶段定义，其中历史“v0.1 发布”现指 V1 完整产品发布。里程碑以证据退出，不能用页面数量或“可以生成一张图”替代完成标准。

## M0 — 先验证最贵的技术假设

输入：最小品牌资料、授权参考图、两个隔离的测试项目、已登录原生 runtime、用户同意的测试调用范围。

交付一个可重复运行的最小 adapter 试验及报告，验证研究引用、参考图、生图、编辑、文件回收、预算/路线可见性和 Windows 隔离。锁定实际 CLI 与协议版本，记录每一项未支持能力。

**通过条件：** 至少一条原生路线完成“指定项目上下文 → 文本/研究 → 参考图生成 → 一次定向修改 → 本地文件回收”；隔离/计费边界通过；恢复演示可对账或明确停在结果未知。输出证据必须是真实文件及运行记录。

**失败分支：**

- 原生图片工具不可用：保留知识与创意成果，明确选择继续排查、将发布缩成技术预览，或由用户选择 BYOK。修改 PRD 发布定义后才能称为新范围完成。
- 图片可用但质量不足：在相同 brief 和修改预算下比较候选图片路线，不能靠无限重抽“证明成功”。
- 沙箱无法阻止跨项目/凭证访问：该 adapter 不得进入自动生产。改为受控工具路径或人工桥接，保留阻断记录。
- 计费/内部调用不可观察：准确声明控制粒度；不能宣称硬预算已通过。

## M1 — 最小创作闭环

建立两个长期项目、最小 Brand Pack、确认版本、独立研究/洞察任务、项目创意库与收藏、Creative Set 版本关联、选择后制作和本地资产归档。提供一个经过检查的基础 Skill，并锁定内容版本。

**退出证据：** 每项目完成一个单图 set；可仅构思并收藏，重启后从收藏继续；从资产追溯输入快照；新任务默认复用已有研究；项目切换无上下文污染。这个里程碑是内部验证，不等于全部 v0.1 发布条件。

## M2 — 补齐日常生产和恢复

加入双制作模式、图片/文案局部修改、Skill 管理、Review、反馈范围、内容覆盖、成品导出、备份恢复、失败/取消/重启处理。

**退出证据：** FR-01～FR-16、FR-19～FR-20 的功能 AC 全部通过；两项目各完成 Paid 与 Organic；T-29～T-36 覆盖跨次复用、记忆取材和备份；故障注入测试无重复成功步骤或跨项目输出。FR-17/18 仍为 P1。

## M3 — 对照质量与本地发布

运行[评测协议](evaluation.md)，比较原手工流程与工作台，记录全部失败及人工操作时间。提供安装、连接、使用和恢复说明；锁定依赖、选择仓库 license、整理第三方归属。

**退出证据：** PRD 发布条件及质量门槛通过，已知限制公开。若质量未达标，继续改善制作/上下文环节，不能用更多 provider 数量替代质量。

## 后续版本候选

| 候选 | 进入条件 |
|---|---|
| 第二 provider / 更智能的 route 建议 | 第一条路线有可量化的质量、费用或能力缺口 |
| 网站/PDF 导入 | 手动录入成为主要时间负担，且抽取准确率能验证 |
| Carousel / 更多模板 | 真实内容任务反复需要成组叙事，单图组合不够 |
| 语义检索 | 结构化/全文检索在真实资料规模下显著漏召回 |
| 发布/排期 | 制作闭环稳定，用户明确需要承担平台授权与失败恢复成本 |
| 团队/远程/云同步 | 用户范围明确改变，独立重新定义产品需求 |
| Insight/图片等通用收藏、独立 Saved 分层 | 创意收藏之外出现明确且反复的跨次取用需求 |
| 定时研究刷新 | 用户明确需要频率、费用范围与更新审批机制；不改变手动默认 |
| 表现数据接入与效果分析 | 有可授权的真实指标、口径与归因条件；不把采用当转化 |
| 自动偏好模型 / 洞察强化 | 有可验证收益及用户确认机制；v0.1 先用有范围的历史例子检索 |

## 风险登记

| ID / 优先级 | 风险 | 应对与责任 | 触发/退出条件 |
|---|---|---|---|
| R-01 / 高 | 原生图片/文件能力无法完整集成 | 架构负责人执行 M0，按路线记录结果 | 不能通过则不承诺自动制作 |

| R-05 / 高 | 生成内容出现未经确认承诺 | Brand Pack claim 引用 + Review + 最终用户检查 | 最终交付零已知未确认承诺 |
| R-06 / 中 | 上游 API/实验协议变化 | 锁版本、契约测试、能力快照失效 | runtime/认证/工具配置升级即重测 |

| R-08 / 中 | 备份不完整或 schema 升级损坏 | 一致性备份、manifest 校验、新目录恢复 | 实际恢复试验失败阻断发布 |
