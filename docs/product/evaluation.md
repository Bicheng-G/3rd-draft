## 当前 v0.1 的证明对象

本次证明“先前积累能影响后续创作”，不以自动研究、单次生成成功或组件读写替代。使用明确标记的合成测试项目 A/B，不冒充真实品牌、客户评价或效果数据；真实 runtime 的最小成功样本是 **两次创作调用**，中间重启本地服务。第一次的作品与用户反馈先通过应用持久保存；第二次只提交新的创作目标，不在 brief 中重复该反馈。

运行前固定[关闭标准](validation-v0.1.md#关闭标准)、输入及允许调用范围。保留两次作品原文或私有证据位置、版本/文件哈希、context manifest、被实际发送的上下文证据、能力内容哈希、runtime/认证路线、尝试状态和未知用量。记录所有失败与人工介入；若失败需要修复，新增运行并解释原因，不能只选最好的结果。

验收同时检查取材与作品：第二次 manifest 应选入前次作品/反馈并说明理由；实际文字应遵循其中具体创意判断，例如将表达重心或语气按已存反馈改变。仅出现引用 ID、模型自称“已复用”或预写固定答案均不算通过。此观察支持该样本的跨次复用，不证明普遍质量提升、长期偏好学习或营销效果。

在同一夹具加入不相关材料及项目 B 的识别信息，验证有界相关性选材和零跨项目污染。品牌知识只有显式用户确认才生效；反馈的作用范围必须明确且不能隐式升级。自动化测试覆盖归档校验、旧版不可变、非法项目引用、本地请求边界和失败/结果未知；受控假 runtime 用于故障注入，真实链路仍须实际 runtime 与浏览器验证。第二次执行不依赖延续前次 provider 聊天。

本次选择原 T-01/02/13/18/23/25/27/31/34/35 的适用部分，不将部分场景写成完整 T 场景通过。下文 12 个图像 brief、配对视觉评分、时间节省、多角色与完整 T-01～T-36 保留为 **V1 评测基线**；原“v0.1”质量门槛不再阻塞本次文本 Walking Skeleton，也未因此被验证。

## V1 完整质量评测（保留原协议）

以下数值为建议门槛，不是观测结果。样本用于个人产品决策，不宣称统计上证明某模型全面领先。

## 需要回答的问题

1. 工作台能否在真实品牌任务上达到现有手工流程的质量？
2. 人工搬运、选择、修订和归档时间是否减少？
3. 哪些任务值得拆给多个角色，哪些用单角色或固定程序更好？
4. 失败、限流、取消和重启是否可恢复，项目与费用边界是否可靠？
5. 同一项目跨次使用时，是否少问重复问题、复用正确的研究/洞察与收藏，同时保留新创意空间？

## 样本与对照

建立 12 个固定 brief：2 个项目 × Paid/Organic 2 种模式 × 3 类表达（参考产品/场景摄影、文字信息型海报、插画）。在品牌真实需要的范围内覆盖中英文；不强行为了测试创造无业务意义的语言要求。

每个 brief 保存目标、受众、确认事实、禁止承诺、参考资产、语言、尺寸、期望内容和旧流程产物。至少 4 个案例包含产品/角色一致性的定向修改；至少 1 个项目没有完整 design system。

比较两条路径：

- A：用户当前的 ChatGPT Project → Nano Banana 手工流程。
- B：工作台选定的原生 adapter 和同样的任务资料。

历史作品可作视觉参考，但不能凭记忆估计当时耗时。对相同 brief 重新计时，或者把“只有旧成品、无耗时”样本单独报告，不混入节省率分母。

每条路径每个 brief 提供 6 个创意候选、选择 1 个制作，允许 1 次初始生成与最多 2 次定向修改。提示词可按模型原生用法适配，但不能引入另一方没有的产品事实或额外参考图；记录所有人工干预。

对 4 个高风险案例各重复一次，用于观察随机性。主结果仍报告 12 个固定 brief，重复结果单列。任何新增路线使用相同夹具与预算，不能选自己最好的一轮与对方第一轮比较。

## 指标和建议门槛

| 指标 | 定义 | v0.1 建议门槛 |
|---|---|---|
| 可用交付率 | 在限定修改次数内，被用户认为可发布/投放的套数 ÷ 尝试套数 | 主样本至少 10/12，且不低于手工路径 |
| 配对视觉质量 | 对同 brief 的 A/B 结果按下述量表评分，尽量隐藏 provider 标签 | 工作台平均分不低于手工；任一表达类别不能明显退步 |
| 人工操作时间 | 阅读/选择、改文案、搬运、整理与主动修订分钟数；模型等待另记 | 以有可靠计时的配对样本计算，中位数节省至少 30% |
| 一次可用率 | 首次图片及文案即被采用的套数 ÷ 尝试套数 | 报告与基线差异，用于定位返工；不单独代替质量门槛 |
| 修改成功率 | 完成目标修改且需保留要素未明显漂移的次数 ÷ 修改尝试数 | 样本内至少 80%，并报告实际分子/分母 |
| 血缘完整率 | 最终资产可追溯至有效快照/引用的数量 ÷ 最终资产数量 | 100% |
| 未授权费用/越界 | 故障与隔离测试中发生未授权 API 调用或跨项目访问 | 0 次 |
| 未确认承诺 | 最终采用交付中出现未被确认且无依据的价格/效果/服务保证 | 0 项；发现即返工 |

对“明显退步”的操作定义：某类 4 个主样本的平均评分下降超过 0.5/5，或用户判为不可用的数量增加。门槛应在正式测试前确定，不能见到结果后调整以让其通过。

视觉量表各 1～5 分、等权：回应 brief、创意表达、品牌/产品一致性、文字可读性、构图与完成度。严重事实错误、错误 logo/价格/产品外形是单独阻断项，不能靠平均美观分抵消。

尽量随机化文件名与显示顺序，隐藏 provider 标签；若水印/明显风格使盲评不可行，记录限制。首个评审人是用户，独立第二人可作为后续改进，v0.1 不声称无主观偏差。

## 多角色对照

从固定样本挑 4 个任务：2 个用户明确选择补充研究，2 个资料充分。对照“单一强 agent + 相同 skills”与“按需研究/策略/制作/Review 角色”。保持输入、图片修改预算和最终评审方式一致，报告推理调用数、耗时和可用率。新资料不足本身不授权自动研究。

只有收益超过增加的人工等待/用量，才扩大默认角色激活。角色结构保留，简单 post 可以用较少执行任务完成。此对照需要单独的明确测试预算，不因文档存在就自动开始消耗用户额度。

## Living Project 跨次复用评测

使用两个隔离项目，各执行三个分开的会话：第一次明确选择研究/洞察并生成创意；第二次收藏两个、只制作一个；第三次在重启后从另一收藏直接发展并制作。另做一次取消收藏与私有备份恢复。可用受控时间推进模拟间隔，不把模拟称为长期实测。

记录重复输入品牌背景的次数、人工操作时间、自动研究/生图的意外调用数、选入上下文的相关性及版本、未制作点子的可找回性。硬性通过项是 T-29～T-36 全部通过、未授权调用/跨项目召回为零、引用与收藏恢复完整。用户评价新创意是否重复与是否有帮助，报告原始观察，不设置“第 50 次一定更好”的未验证承诺。

如比较有/无创意历史的生成质量，使用相同当前 brief、品牌事实、模型和预算，单独标明历史资料是实验变量；记录所有候选和拒绝，不能挑最好结果。收藏、采用、导出与手动发布分别计数，均不代替 CTR/转化数据。此评测未执行，不声称已经产生复利。

## 报告模板

每份报告包含：日期、应用/adapter/runtime/Skill 版本、认证路线、输入材料哈希、样本选择、配置与预算、全部运行（包括失败）、指标分母、未知用量、人工介入、评分、问题与下一决策。

报告开头明确 `PASS / FAIL / INCONCLUSIVE`。缺少旧素材、配对计时或实际认证证据时用 INCONCLUSIVE，不填写推测数值。账号级订阅用量若同时有其他任务，不能当成此创作的精确成本。
