## 当前推进：正式 logo 与真实工作流（2026-10-20）

用户明确同意先提交/推送已有改动，再推进正式 logo、RidePass 实测及后续 V1 验收。下方 10 月 5～6 日的停止措辞保留为历史范围。FR-02/07/08/09 现在采用 ADR-018：上传不等于指定；用户在图片库明确选择正式 logo，生成/编辑前必需校验，快照锁定版本/哈希。原生视觉保留独立底图；本地在白色页脚按比例合成正式 logo，后续编辑只使用底图，并重新合成当前指定 logo。首次生成与编辑仍须用户发起；旧文件不覆盖。

原生底图不保证没有额外虚构标识，因此成品采用必须有用户对真实 logo 与额外品牌标识的显式目视确认，模型 Review 不能替代。logo 改版后旧作品仍可查看和草稿导出，新采用/最终导出要求使用当前版本。历史原生图没有独立底图时明确禁止直接指令编辑，须从创意重新制作。caption-only 修改继续保留旧图及其 logo，不产生图片调用；它不用于绕过当前 logo 的采用检查。本地模板使用同一正式 logo 选择；原生作品用于模板时优先取其底图，避免重复嵌入页脚。

此切片不实现自由拖拽、自动标识检测、第二 provider 或自动发布。完整 V1 的两品牌、质量计时和用户采用门槛仍须另证。

## 用户反馈：正式 logo 与可选手工排版（2026-10-06）

RidePass v0.1 dogfood 后，用户明确要求项目有品牌 logo 上传位置，所有生成的图片作品使用上传的真实 logo，禁止生成式 AI 自行设计、重绘或替代 logo。此要求补充 FR-02/07/08/09 的 V1 验收；不是对既有 v0.1 记忆闭环结论的追溯否定。缺少已指定的项目 logo 时，生成/编辑品牌图片作品须明确阻止，不通过虚构标识补齐；独立文字构思仍可使用不完整品牌资料。

用户可明确指定用于制作的上传 logo；制作快照须锁定其资产版本/哈希，生成和指令编辑后的作品均使用该真实资产，保留比例与内容，记录依赖。仅把 logo 当可选参考或写一句 prompt 不能证明此保证。更换 logo 不覆盖历史作品；新增版本使用当前明确指定的 logo。验收须检查实际像素/制作记录，且错误、遗漏或生成的品牌标识不能靠模型自评通过。实现方案尚未选择，本轮只记录要求与现状，不启动 V1 实施。

手工移动 logo 等对象的可视化分层编辑为未来版本 good-to-have，**不构成 V1 必须具备的交互编辑器**。FR-09 原有确定性模板、分层制作记录及自然语言图片编辑要求保留；保存图层参数不等于已有拖拽画布。

## 当前里程碑：领域与隔离修正、原生制作有界可行性（2026-10-05）

用户本轮明确暂停外围 V1 扩展。先修正 CreativeSetConcept 的 set 内决策、AssetVersion 前版本与输入依赖的区别、手工创意的来源和创建上下文；再完成原生图片有界可行性调查。完整 V1 要求和既有 FR/AC/T 编号保留，但不是本轮完成范围。

- FR-19/20：手工创意仍由用户创建且无伪造 run；保存创建目标、显式证据/洞察版本及当时品牌版本基线。手工续作保留来源，品牌变化检查不能因手工编辑丢失；旧资料没有可恢复上下文时明确 unknown。
- FR-13、NFR-01/04：Third Draft 使用自己拥有的 runtime profile；应用不借用或修改个人 Codex 配置、规则、凭证或会话，不要求全局 AGENTS 文件为空。独立 ChatGPT 登录；不复制个人登录凭证。原生 Skill 隔离按下方后继批准为 best effort，发现/加载本身不阻断执行。版本不是唯一兼容条件：二进制/必要权限契约变化后执行有界本地探针，硬性检查全过才允许相应能力，失败关闭；文字/视觉与生图能力分别验证。
- FR-07/08、M0（产品负责人本轮修订）：一次用户显式发起的 Production Action 最多允许 **2 次图片操作**，计数可由 Third Draft harness/runtime 边界强制实施，不要求原生图片接口独自提供限额。runtime 可读取当前项目隔离/staged 文件系统内的内容，但不得读取正常宿主文件或其他 Third Draft 项目；ProductionSnapshot 继续记录用户明确选定的参考图，选定参考图不再是项目隔离区内唯一可读文件。独立应用 profile 须完成自己的交互 ChatGPT 登录及真实订阅路线验证，不依赖或修改个人 Codex profile。所有控制通过后只实现 Generate→不可变 AssetVersion→一次显式指令 Edit→新 AssetVersion / Project Memory；否则仅依据修订后仍未满足的边界记录 BLOCKED 并停止。

本轮批准明确取代此前“每动作只能 1 次图片操作”“只能读取所选参考文件”“限额必须由 native 接口提供”的验收条件。历史负例保留，但“两次操作”以及“越出 approved-input 子目录、仍在当前项目隔离区内”的读取不能单独构成 blocker。批准修订不等于已证明实现，新的可行性结论须附新边界下的运行证据。

**后继批准：原生 Skill 为 best effort（2026-10-05，ADR-017）。** 产品负责人接受个人/native Skill 可能被 runtime 发现或加载；这本身不构成模型或图片阻断，不要求完美指令纯度。保留可靠、简单的抑制设置，实际可观察时记录环境可能含外部 Skill，不为纯度建设新基础设施。硬 P0 是限制正常宿主文件访问、隔离其他项目、固定显式 ChatGPT 订阅路线而不静默 API/BYOK/provider 回退，以及应用独占批准/采用/发布/新增 Production Action 的授权。每个显式 Action 最多 2 次图片操作，授权不跨 Action；文件成功必须由应用取回、验证、归档，不能依赖模型自报。只有 Skill 已被具体证据证明可击穿上述边界且 harness 无法约束，才重新成为阻断理由。旧 Skill 负例保留为观察，不再作为必要兼容性失败。

本里程碑已实现并验证一条应用固定原生工具调用的路线，结论 FEASIBLE：Studio 必须明确选择一个概念版本、逐项选择参考，再点击 Start image generation；编辑从已生成版本选择并填写指令，点击 Start image edit，原版保留。上限 2 是每 Action 的硬上限，当前正常路径各发起 1 次；追加参考不自动取用 brief 中其他资产。回收文件、AssetVersion、lineage/依赖和 Project Memory 均通过应用验证保存，不自动采用或发布。最小限制为最多 5 张 PNG 输入（编辑原版占 1 张）、单张 10 MiB/合计 40 MiB，当前 opaque 输出。真实订阅 Generate/Edit 通过只关闭本里程碑，后续真实社媒工作流质量由 dogfooding 验证，不代表完整 V1 发布验收。证据见 [V1 验证](validation-v1.md)。

无第二 provider、批处理、自主研究或新工作流基础设施。这个里程碑不表示 V1 发布、视觉质量或用户采用已经验收。具体结果与运行分母见 [V1 验证记录](validation-v1.md)。

## 当前 v0.1：跨次创作记忆闭环

本轮用户将 v0.1 定义为 Walking Skeleton，将完整产品定义为 V1；本次只完成前者。核心假设是：项目已积累的知识、创意判断或反馈，经相关上下文选取后，能实际影响下一次创作。闭环为“用户动作 → Project Memory → 相关 Context → 版本化能力 → 实际 Runtime → 作品 → 归档 → Project Memory”。

最小交付是 Windows 本机浏览器工作台：两个隔离项目、文本知识及显式事实确认、一个随应用提供的版本化文本创作能力、原生 ChatGPT 认证的 Codex 文本执行路线、可读取的文字作品归档、有范围的反馈与后续复用。每次任务显示路线、状态、上下文选取和历史来源；品牌事实、作品与反馈分别保存，不把模型结果或收藏自动确认为品牌事实。

关闭标准固定在[本次验证记录](validation-v0.1.md)：至少两次真实创作调用，中间重启本地服务；第二次 brief 不复述已存反馈，但输出能体现其具体影响。并验证不可变版本/哈希、相关性、项目隔离、无静默 BYOK、错误不伪装成功、结果未知不自动重发以及浏览器可用性。通过自动化测试并不替代真实 runtime 和浏览器链路证据。

这些标准选取 FR-01/02/06/11/13/14/15/19/20 的必要部分，不宣称这些 AC 已全部通过。自动研究、图片制作/编辑、完整 Paid/Organic 与收藏/洞察工作流、第三方 Skill 管理、完整备份迁移、视觉质量对照、生产规模能力不属于本次关闭条件。原有完整要求及 ID 保留于下文，作为 **V1 基线**；其中历史文字“v0.1”“第一版”“P0 发布要求”不再扩大本次 Walking Skeleton 范围。[ADR-013](../architecture/decisions.md#adr-013--walking-skeleton-以跨次文本创作证明项目记忆闭环)记录本次实施取舍。

## V1 完整产品基线（保留原需求）

## 目标与前提

在 Windows 本机让一个人完成两个彼此隔离的品牌项目的图文创作。核心体验达到现有“ChatGPT Project 研究/创意 → Nano Banana 生图”流程的质量，减少上下文搬运和返工协调。

Project 是长期工作空间。研究、洞察整理、创意构思、从收藏发展和图文制作可以分别启动、保存和结束；Creative Set 组织一次发展/制作，不要求每次重走研究至生图全链路。

主要执行端是用户已有订阅的 agent runtime。M0 必须先证明至少一条原生图片制作路线可用。Provider 登录成功不能代替生图、文件回收和项目隔离验收。

原基线 P0 现表示 V1 完整产品发布要求；P1 表示在这些要求通过后考虑。表中 AC 和优先级编号保留，细化场景见[评测计划](evaluation.md)。

| FR-19 / P0 | 收藏创意并跨次复用 | AC-19：生成或手动创建的创意均保存到所属项目；收藏固定创意版本，可取消并附原因；重启后可从收藏继续发展，不强制重新生成概念板；同一创意可用于多个 set，改动创建新版本并保留来源；收藏可与已使用并存，取消收藏不删除内容；跨项目引用被拒绝 | U-14、U-15、U-16 |
| FR-20 / P0 | 维护项目洞察与相关创作记忆 | AC-20：洞察整理可由用户独立触发，使用指定证据并保存稳定 ID、版本、适用受众、反例与假设身份；修订不覆盖旧引用；每次创作按项目、相关性、时效和范围选择品牌约束、洞察、历史创意及反馈，ContextManifest 可查选材理由；不全量加载历史，不把收藏/采用转为品牌事实或效果结论 | U-13、U-16 |

FR-17/18 为候选 backlog，不是 V1 发布门槛。图像“局部编辑”在 P0 指自然语言指定修改区域与保留内容；可视化 mask 画笔是 P1，不能混淆两者。

## 第一版的操作约束

- 本地应用身份与 provider 账号分离：一个本地操作者可以连接 provider，不需要先建设云端用户账户系统。
- 不完整的 Brand Pack 可以运行；缺失价格、保证、效果数据时不得补造数值。
- 研究和洞察初始化均可跳过；建项时明确选择才执行，后续仅手动触发。创意任务默认使用已有版本；发现缺口可建议补充，未经用户触发不得启动研究或自动刷新洞察。
- Generate Creative Ideas 可不建立 Creative Set；Generate Ad Set 创建/继续 Paid set 并发展选定方向，仍不自动制作全部图片。历史创意进入新 set 时检查当前品牌事实与 brief，旧批准不得沿用。
- 创意库保存全部结果，Favorites 是其中明确收藏的创意版本视图。收藏、选中制作、实际使用、最终采用与发布是不同动作；不使用一个互斥状态字段混合表达。
- 进入制作时一次确认选定概念、预计调用数、路线和可见的费用/额度信息。授权绑定快照及范围，非每张图重复审批。
- 默认一个 Creative Set 最多选 3 个 concept 开始制作；每个先生成 1 张，最多 2 次定向修改。可在启动前调整，并在超出预算时重新确认范围。
- 用户可以每次只制作 1～2 个 post，其他创意仍可继续使用；上述最大 3 个是原有可调整上限，不是最低批量。不得为了完成整个 set 自动制作所有候选。
- 首版应用默认全局最多同时运行 2 个 agent 任务；同一图片路线同时最多 1 个制作调用。账号限流可以进一步收紧。
- 图片比例预设 1:1、4:5、9:16 是本产品输出选项，不是承诺某平台所有广告位都接受。模型不支持时先说明重排/裁切方案，不能拉伸产品。
- 客户可见成品包与内部完整项目备份分开：成品默认去除内部 prompt、研究摘录和私有数据；内部血缘仍保留。
- FR-16 的私有备份也包含独立创意、收藏、洞察版本和跨 set 引用。收藏不使内部知识进入普通成品包。
- 唯一主 Agent 是待评测建议；保留研究、策略、制作、Review 的逻辑职责，不要求每次启动所有角色。CTR/转化接入、定时研究、自动偏好规则与自动洞察强化不纳入 v0.1。

## 非功能需求

| ID | 要求 | 验证方式 |
|---|---|---|
| NFR-01 | 项目隔离覆盖数据、文件、检索、缓存、runtime thread 和临时输出 | 两项目诱导读取/交叉 ID/路径穿越/会话复用测试全部拒绝 |
| NFR-02 | 本地服务只监听 loopback；浏览器不持有 provider 凭证 | Host/Origin 检查、会话授权、CSRF/跨站请求拒绝；日志扫描 |
| NFR-03 | 任务状态先持久化后通知 UI；文件成功校验后才标记完成 | 杀进程、断流、重复事件、磁盘写入失败场景 |
| NFR-04 | 用户确认、预算和 provider 切换由代码控制 | agent 输出无法自行批准或突破预算 |
| NFR-05 | 核心状态不依赖 provider 聊天记录 | 清除执行会话后仍可查看/续作现有 set；必要时以快照开新任务 |
| NFR-06 | 产品 UI 使用英文；每个 brief 明确内容语言，两者独立 | 英文导航、表单、状态、反馈及错误信息；英文界面可生成、编辑、导出英文和中文内容，保留文字编码 |
| NFR-07 | 本地操作不等待模型完成 | 在记录硬件条件的 1,000 资产夹具上，项目切换/列表查询 p95 ≤ 1 秒；模型时长另记 |
| NFR-08 | 可解释的用量记录 | 每次尝试记录路线、状态、调用数；有 token/费用则显示，无则 unknown，不显示 0 伪装免费 |

NFR-07 是待验证目标，不是已有性能承诺。针对实际 1,000 图片夹具发现的全量 DOM 阻塞，FR-11 的图像库和 Studio 使用每页 50 张、可见视图按需渲染；筛选作用于全部保存记录，总数不变，用户可用上一页/下一页/末页/页码访问所有版本。分页不是删除历史或减少导出范围，性能结果与测量方法另见 V1 验证记录。离线支持本地浏览、编辑文本和导出；不承诺云模型离线生成。

## V1 发布条件（原 v0.1 完整发布条件）

1. FR-01～FR-16、FR-19～FR-20 的 AC 通过，M0～M3 的退出证据齐全；FR-17/18 仍为 P1。
2. 两个项目分别完成一套 Paid 和一套 Organic；生成、至少一次修改、采用、导出和恢复均可演示。
3. [质量评测](evaluation.md)达到约定目标；没有跨项目泄漏、未授权 API 费用或未确认产品承诺混入最终交付。
4. 安装/启动、运行时接入、数据目录、备份和已知限制有用户文档；产品源码许可证已明确。
5. 演示跨次使用：手动研究并整理洞察 → 仅生成创意 → 收藏两个 → 今天制作一个 → 重启后从收藏直接发展另一个；已有研究不自动重跑，未选想法与所有历史引用保留。对应 T-29～T-36。

## 需求变更规则

新功能必须说明服务哪个用户任务、替代哪一步人工工作、增加哪些数据/权限/费用，以及何种证据支持优先级。对范围、认证、记忆或编排的变更更新 ADR；先修订基线，再扩大实施。
